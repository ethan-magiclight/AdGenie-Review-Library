## 0. 三句话结论

1. **能力底座的交付物不是"提示词"，是一份填好的《模板规格》。** 内容团队如果只交提示词，产品就做不了参数化、做不了镜头级重做、做不了质检——这三件事是 AdGenie 区别于"套壳生成器"的全部。规格定义见 §2.2，这是本文档最需要先拍板的东西。
2. **信息架构要从"筛选优先"改成"推荐优先"。** 现在的流程是「首页 → 模板库 → 按品类/题材/风格筛」。小 B 用户不认识"美学 B-Roll""痛点对比"这些行业词，让他筛等于让他做他做不了的决定。正确顺序是「传商品 → 系统自动识别并推荐 3-5 个 → 选一个」，筛选是给老手的逃生通道，不是主路径。详见 §3.1。
3. **首批砍到 4 品类 × 6 题材。** 219 条案例的分布极度不均，耳机一个品类占 63 条，而开箱只有 1 条、真人推荐 2 条。硬撑 6×10 的矩阵会得到 33/60 的空洞感；收到 4×6 后覆盖率是 18/24，只差 6 个格子，补齐成本可控。清单见 §4.1。

## 1. 产品定义与边界

### 1.1 一句话

给**没有视频团队的电商小 B**，用「商品素材 + 卖点 + 选一个模板」换一条**30-45 秒、能直接发的品牌广告片**。

### 1.2 边界（决定了后面所有取舍）

| 做 | 不做 |
|---|---|
| 少而精：单个用户月产 3-10 条 | 批量投放素材、一键出 50 条 |
| 品牌质感、产品美学 | 效果广告、A/B 测试、投放数据回流 |
| 模板驱动、参数化配置 | 开放式 prompt 编辑、时间线剪辑器 |
| 傻瓜式：默认值能直接出片 | 专业工具的完整可控性 |

**这条边界的直接后果**：单条成本可以做高（用户一个月只做几条），所以允许多候选生成后自动择优、允许生成失败自动重跑。这是相对通用 AI 视频工具的质量空间，要用满。

### 1.3 目标用户画像

- 耳机数码 / 美妆护肤 / 香水 / 口红 类目的商家老板、品牌运营、电商运营
- 无视频团队，不懂脚本分镜，**也不懂"题材"这个词**
- 手里有：商品白底图、详情页图、可能有一段简单实拍
- 内容去向：社媒自发 / 给 KOL 用
- 价格敏感，但愿意为"比普通投放素材更有质感"付更高单价

## 2. 产品能力：底层能力底座

### 2.1 三层能力模型

```
┌─ L3 应用层 ── 推荐、配置表单、预览、重做、商品档案
├─ L2 引擎层 ── 模板解释器 · 生成编排 · 自动质检 · 合成出片
└─ L1 资产层 ── 模板库（Template Spec）· 素材库 · 风格库 · 音乐库
```

**内容团队交付 L1，研发交付 L2/L3。** 两边靠 §2.2 的规格解耦——这是整个项目能不能并行推进的关键。

### 2.2 模板规格（Template Spec）— 核心交付物

这是内容团队与研发之间的**唯一契约**。一个模板 = 一份 Spec = 一个可执行的视频方案。

```yaml
# ============ 元信息 ============
id: earphone-tvc-001
name_zh: 未来概念城市光影大片
name_en: Future Concept City Film
category: [earphone, watch]          # 适配品类，可多选
genre: tvc                            # 题材
duration: 35                          # 秒
aspect: ["9:16", "16:9"]              # 支持比例
style_tags: [科技感, 冷调, 高对比]
ref_case: "AI Concept Commercial for vivo Earbuds"   # 逆向来源，内部可见

# ============ 素材需求（产品据此校验和引导用户）============
assets_required:
  - key: product_main
    label: 产品正面图
    required: true
    hint: 建议纯色或透明背景，产品占画面 60% 以上
  - key: product_angle
    label: 产品 45° 侧面图
    required: false
    fallback: 用 product_main 生成           # 缺失时的降级策略
  - key: brand_logo
    label: 品牌 Logo
    required: false
copy_slots:
  - key: selling_points
    label: 核心卖点
    count: 3
    max_len: 12                              # 字数硬约束，超了排版会崩
  - key: brand_name
    max_len: 10
  - key: slogan
    max_len: 16
    required: false

# ============ 对外露出的参数（严格白名单）============
exposed_params:
  - key: theme_color
    type: color
    default: "#C6FF3A"
    affects: [shot_3, shot_5, subtitle_style]   # 声明影响哪些镜头，用于增量重渲
  - key: style_preset
    type: enum
    options: [科技冷调, 温暖质感, 极简纯白]
    default: 科技冷调
  - key: duration
    type: enum
    options: [15, 30, 45]
    default: 35
    shot_plan:                                  # 不同时长用不同镜头子集
      15: [shot_1, shot_3, shot_6]
      30: [shot_1, shot_2, shot_3, shot_5, shot_6]

# ============ 分镜（有序，每镜头独立可重生成）============
shots:
  - id: shot_1
    type: B                      # A=产品镜 / B=氛围镜 / C=信息镜
    duration: 4
    prompt_template: "..."       # 内部，不对外露出
    camera: 缓慢推进
    lighting: 侧逆光冷调
    ref_bindings: []             # B 类镜头不绑定用户素材
  - id: shot_3
    type: A                      # 产品出镜，还原度关键镜头
    duration: 5
    prompt_template: "..."
    ref_bindings:
      - asset: product_main
        role: subject_reference   # 主体参考，模型据此保持产品一致
        weight: high
    product_anchor:               # ← 产品在画面里怎么摆
      position: center
      scale: 0.55
      angle: front
      occlusion: none
    camera: 环绕 30°
    qc:                           # 该镜头的质检要求
      product_visible: true
      similarity_threshold: 0.82  # 与 product_main 的视觉相似度下限
  - id: shot_6
    type: C
    duration: 3
    text_layer: "{{brand_name}} · {{slogan}}"
    motion: 字符逐个淡入

# ============ 音轨 ============
audio:
  bgm_style: 电子 / 低频推进
  beat_sync: [shot_3.start, shot_5.start]     # 卡点位置
  vo_script: null                              # 本模板无旁白
  sfx: [shot_2: whoosh, shot_6: impact]

# ============ 成片级质检 ============
qc_rules:
  - 产品在成片中总出镜时长 ≥ 8s
  - 所有 A 类镜头 similarity 均达标
  - 字幕无溢出、无遮挡产品
  - 总时长偏差 ≤ 1s
```

**几个设计要点，都不是可选项：**

- **`type: A/B/C` 三类镜头必须显式声明。** A 类（产品出镜）是唯一有还原度风险的，也是唯一有商业价值的；B/C 类基本可控。质检、重跑、成本预算全部按这个分类走。
- **`product_anchor` 是普通 AI 视频脚本里没有的一层。** 因为产品不是凭空生成的，是要"放"进画面的，必须写清位置、占比、角度、遮挡。这一层也是未来 P2「参考视频反解」最难的部分——反解不只要看懂剧情，还要看懂构图和布光。
- **`affects` 字段让参数改动可以增量重渲。** 用户改个主题色只重跑 2 个镜头，不重跑全片。没有这个字段，改一个字就要等 10 分钟、烧一次全额成本。
- **`fallback` 让模板对素材缺失有容错。** 小 B 大概率只有一张白底图，模板不能因此不可用。

### 2.3 生成管线与还原度策略

```
商品输入 ──┬─ 链接解析 → 标题/卖点/类目/主图
           └─ 图片上传 → 抠图去背 → 商品资产
                                    │
选定模板 → Spec 解释器 ─────────────┤
                                    ↓
                            [第一段] 分镜故事板（静态图，20-40s 出）
                                    ↓  ← 用户确认 / 局部换图
                            [第二段] 逐镜头视频生成（并行）
                                    ↓
                            自动质检（A 类镜头还原度 + 成片规则）
                                    ↓  ← 不达标自动重跑，最多 N 次
                            合成：转场 + 字幕 + BGM 卡点 + 调色
                                    ↓
                                  成片
```

**两段式生成是这个产品体验设计上最重要的一个决定。**

30-45 秒的片子按 Seedance 类模型 5-10s/镜头算，是 5-8 个镜头，串起来生成大概 5-15 分钟。让小白用户对着进度条干等 10 分钟、然后发现方向不对，是最致命的流失点。先出一版静态分镜故事板（几十秒），让用户确认"就是这个感觉"再烧视频生成，等于同时解决了三件事：感知等待、方向纠错、成本控制。

**关于还原度，需要更正我之前的判断。** 讨论时你选了「必须 100% 还原」，我当时给的是分层合成路线（AI 只生成背景，产品用真图贴合成）。但你现在明确要用 Seedance 2.0 —— 这类模型支持多图参考驱动、主体一致性本身就是它的强项，走合成反而会牺牲光影融合的自然度。所以实际路线应该是：

| 层次 | 手段 |
|---|---|
| 主路径 | 多图参考驱动生成，`ref_bindings` 把用户商品图绑成 subject reference |
| 保障 | A 类镜头生成后做还原度质检（视觉相似度 + Logo 可辨识检测），不达标自动重跑 |
| 兜底 | 连续重跑仍不达标 → 该镜头降级为合成（真图 + AI 背景），或替换为 B 类氛围镜 |

「100% 还原」的目标不变，实现方式从"绕开生成模型"变成"用生成模型 + 质检闸门把不合格的挡住"。质检闸门这一环没有人工兜底，必须做实——**它的投入基本等同于一个人工审片岗，早期别省**。

> ⚠️ **待确认**：你说的"SD 2.0"我理解为 **Seedance 2.0**（首页设计方案里提到参考 Higgsfield SEEDANCE 2.0 视觉）。如果指的是别的模型请纠正——模型的单镜头时长上限、多图参考能力、分辨率直接决定分镜结构和整条管线，这个不能猜。

### 2.4 内容团队的工作流与交付标准

给内容小组的任务不是"写提示词"，而是"把一条样片变成一份可执行、可复用、经过验证的 Spec"。

```
① 选样片      从案例库挑，优先「模板化程度=高 + AI可实现度=高」（219 条中 130 条满足）
② 拆解        逐镜头标注：时长 / 镜头类型 / 运镜 / 构图 / 光线 / 产品位置 / 文字层
③ 写 Spec     按 §2.2 格式填写，prompt_template 用变量占位而非写死某个商品
④ 三品验证    用 3 个不同商品（含一个"难看的"白底图）各跑一遍，都可用才算通过
⑤ 参数标定    确认 exposed_params 的每个取值都不会出废片，标定 affects 影响范围
⑥ 上架        补中英文模板名 + 适用说明（禁止出现真实品牌名，沿用现有规范）
```

**验收标准（建议写进给内容团队的任务书）：**

- 三品验证 3/3 可用，不是 2/3
- 参数任意组合下不出废片（枚举值笛卡尔积全跑一遍）
- 素材只给一张白底主图时，靠 `fallback` 仍能出片
- 单模板端到端生成成功率 ≥ 80%（含自动重跑）

**工作量估算**：单模板从拆解到上架约 **2-4 人天**（含验证和返工）。首批 30 个模板 ≈ 60-120 人天。这个数要提前跟内容团队对齐，否则排期会崩。

### 2.5 商品理解能力（链接解析）

首页那个"粘贴商品链接"的入口，实际能力边界要说清楚：

| 能拿到 | 用来干什么 | 可靠性 |
|---|---|---|
| 商品标题、类目 | 自动选中品类 Tab、过滤模板 | 高 |
| 详情文案 | LLM 提取 3 条卖点候选，**用户确认后**使用 | 中，必须让用户改 |
| 商品主图 | 仅作品类识别和缩略展示 | **不建议直接用于生成** |

⚠️ 电商主图普遍带水印、大促角标、拼接文字、模特叠加，直接喂给生成模型出来的片子质量会很差。**链接解析的定位是"提卖点 + 认品类 + 荐模板"，图片素材仍应引导用户单独上传干净原图。** 这一点要在 UI 上讲清楚，否则用户会以为贴个链接就完事了，然后拿到一条废片。

## 3. 产品框架

### 3.1 信息架构的关键调整：推荐优先

**现状设计**：首页 → 模板库（品类 / 题材 / 色彩风格三重筛选 + 搜索）→ 配置 → 生成

**问题**：小 B 用户不具备做这些筛选的知识。"美学 B-Roll"是什么？"痛点对比"和"产品对比测试"有什么区别？他脑子里只有两句话——"我要一条看起来很贵的耳机广告"，或者"我要让人知道我的降噪很牛"。让他面对一个三维筛选器，等于把产品经理的分类学负担转嫁给用户。

**调整后的主路径**：

```
首页 ──传商品（链接/图）──→ ② 商品确认页 ──→ ③ 推荐结果 ──→ ④ 配置 ──→ ⑤ 生成 ──→ ⑥ 成片
                                自动识别品类      3-5 个模板        4-6 个参数
                                自动提取卖点      直接可预览        默认值可直接出片
                                用户确认/改       「看看全部」→模板库
```

模板库不消失，但**降级为二级入口**：从推荐结果页的"看看全部模板"进，或从导航栏进。它服务的是回访用户和明确知道自己要什么的人。

**同时建议：把"题材"翻译成用户能听懂的话。** 内部继续用 genre 做数据字段，前端展示换成目的导向的措辞：

| 内部 genre | 前端展示（建议） |
|---|---|
| tvc | 品牌大片感 |
| closeup | 秀细节做工 |
| multi | 360° 看全貌 |
| broll | 生活场景氛围 |
| demo | 讲清怎么用 |
| tryon | 上身/上脸效果 |
| unbox | 开箱仪式感 |
| ugc | 像真人在推荐 |
| story | 讲个小故事 |
| versus | 对比出效果 |

电视机上的频道键是很好的视觉隐喻，但键上的字要换成右列这种——**用户按的是"我想要什么效果"，不是"这是什么题材"**。

### 3.2 页面清单

| # | 页面 | 状态 | 核心职责 | 优先级 |
|---|---|---|---|---|
| ① | 首页 | ✅ 已做 | 品牌调性 + 能力展示 + 转化入口 | — |
| ② | 商品确认页 | ❌ 缺 | 解析结果确认、抠图预览、卖点编辑 | **P0** |
| ③ | 推荐结果页 | ❌ 缺 | 3-5 个模板卡，可预览可切换 | **P0** |
| ④ | 模板库 | ❌ 缺 | 全量卡片 + 筛选 + 搜索（二级入口） | P0 |
| ⑤ | 模板配置页 | ❌ 缺 | 参数表单 + 素材槽 + 卖点录入 | **P0** |
| ⑥ | 分镜确认页 | ❌ 缺 | 静态故事板预览、局部换图、确认出片 | **P0** |
| ⑦ | 生成中 | ❌ 缺 | 分阶段进度、可离开可回来 | P0 |
| ⑧ | 成片页 | ❌ 缺 | 播放、下载、**镜头级重做**、改参数重生成 | **P0** |
| ⑨ | 我的作品 | ❌ 缺 | 历史记录、草稿续做 | P1 |
| ⑩ | 我的商品（档案） | ❌ 缺 | 商品素材 + 卖点 + 品牌信息复用 | P1 |

②⑥⑧ 是三个最容易被漏掉、但决定「傻瓜式」成立与否的页面：② 让用户在花钱前确认输入对不对，⑥ 让用户在等待前确认方向对不对，⑧ 让用户在拿到片子后能改。缺任何一个，产品都会退化成"抽卡机"。

### 3.3 数据模型

```
User
 └── Product（商品档案，P1 落地，但 P0 就要建表）
      ├── assets[]      主图 / 45°图 / 细节图 / 佩戴图 / Logo
      ├── selling_points[]
      ├── brand { name, logo, color, slogan }
      └── category

Template（模板 = §2.2 的 Spec）
      ├── meta / assets_required / copy_slots
      ├── exposed_params[]
      ├── shots[]
      └── qc_rules[]

Project（一次创作）
      ├── product_id + template_id
      ├── param_values{}          用户填的参数
      ├── storyboard[]            第一段产出：分镜静态图
      ├── shot_renders[]          第二段产出：每镜头视频（可单独重跑）
      ├── output                  合成成片
      └── status / cost / qc_report
```

**`shot_renders[]` 必须是独立可寻址的记录**，否则"重做第 3 个镜头"这个功能做不出来，用户每次不满意就只能整条重来。

### 3.4 对外参数体系（全局白名单）

不开放底层提示词，只露出这些。**每个参数都必须有一个能直接出片的默认值**——小白用户什么都不改点生成，也应该拿到一条能用的片子。

| 参数 | 类型 | 来源 | 说明 |
|---|---|---|---|
| 品牌名称 | 文本 ≤10 字 | 商品档案带入 | |
| 品牌 Logo | 图片 | 商品档案带入 | 可空，空则片尾只显示品牌名 |
| 主题配色 | 取色器 + 预设 | Logo 自动取色为默认值 | |
| 画面风格 | 枚举 3-4 项 | 模板定义 | 各模板选项不同 |
| 视频时长 | 15 / 30 / 45s | 默认取模板原时长 | 影响镜头子集 |
| 画面比例 | 9:16 / 16:9 / 1:1 | 默认 9:16 | 模板需声明支持哪些 |
| 核心卖点 | 3 条 × ≤12 字 | 链接解析自动填，用户可改 | 字数是硬约束 |
| 字幕开关 | 布尔 | 默认开 | |
| 旁白配音 | 关 / 音色 A-D | 默认关 | 模板有 vo_script 时才可选 |
| 背景音乐 | 模板预设 / 3-5 个备选 | 默认用模板预设 | 不做完整音乐库 |

## 4. 需求方案细化

### 4.1 首批品类 × 题材清单（基于 219 条案例的实际分布）

**先看现实。** 现有 91 张卡片在 6 品类 × 10 题材上的分布：

| 品类＼题材 | 品牌大片 | 秀细节 | 360° | 氛围 | 讲功能 | 开箱 | 上身 | 真人 | 故事 | 对比 | 合计 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 耳机数码 | 5 | 7 | 10 | · | 5 | 1 | 2 | 1 | · | 2 | **33** |
| 美妆护肤 | · | 3 | 2 | 3 | 4 | · | 5 | 1 | · | 3 | **21** |
| 香水 | 5 | · | · | 3 | · | · | 2 | · | 3 | · | **13** |
| 口红彩妆 | 2 | 3 | 2 | 1 | · | · | 3 | · | · | · | **11** |
| 运动鞋服 | 1 | 1 | 2 | 1 | · | · | 1 | · | · | · | **6** |
| 腕表配饰 | 2 | 2 | 2 | · | 1 | · | · | · | · | · | **7** |
| **合计** | 15 | 16 | 18 | 8 | 10 | 1 | 13 | 2 | 3 | 5 | **91** |

**两个结论直接从数据里出来：**

1. **人物出镜类题材（开箱 1、真人 2、故事 3）几乎是空的，且这不是采集疏漏。** 品牌官方发布的高质量广告本来就以产品本体表现为主；开箱/UGC 是创作者内容，质量参差，也不"高级"。这跟 AdGenie「品牌质感」的定位其实是冲突的。**建议首批直接放弃人物出镜类**——它属于 TopView 的主场（UGC 数字人），不是你的差异化所在。
2. **运动鞋服（6）和腕表配饰（7）素材太薄**，撑不起一个品类 Tab。建议 P1 再上。

**首批建议：4 品类 × 6 题材 = 24 格，现有覆盖 18/24。**

| 品类＼题材 | 品牌大片 | 秀细节 | 360° | 氛围 | 讲功能 | 上身 |
|---|---|---|---|---|---|---|
| 耳机数码 | ✅5 | ✅7 | ✅10 | ⚠️ **缺** | ✅5 | ✅2 |
| 美妆护肤 | ⚠️ **缺** | ✅3 | ✅2 | ✅3 | ✅4 | ✅5 |
| 香水 | ✅5 | ⚠️ **缺** | ⚠️ **缺** | ✅3 | ⚠️ **缺** | ✅2 |
| 口红彩妆 | ✅2 | ✅3 | ✅2 | ✅1 | ⚠️ **缺** | ✅3 |

**需补齐的 6 个格子**（给内容/调研团队的定向采集清单）：
`耳机×氛围`、`美妆×品牌大片`、`香水×秀细节`、`香水×360°`、`香水×讲功能`、`口红×讲功能`

其中「香水×讲功能」在现实中就很少见（香水没什么功能可演示），建议评估后直接隐藏该格，改为 3 品类有此题材。

**首批模板数量目标：**

| 层级 | 格子 | 每格模板数 | 小计 |
|---|---|---|---|
| 主打（耳机 × 大片/秀细节/360°） | 3 | 4 | 12 |
| 常规（其余有素材格子） | 15 | 1-2 | 22 |
| 补齐格子 | 6 | 1 | 6 |
| — | — | — | **≈ 40** |

按 §2.4 的 2-4 人天/模板估，**首批 ≈ 80-160 人天**。若团队规模跟不上，优先级从上往下砍，先保「耳机数码」这一列做深——它案例最多（63 条）、AI 可实现度最高、也最符合品牌质感定位。

### 4.2 里程碑

| 阶段 | 目标 | 交付 |
|---|---|---|
| **M0 定标准** | 拍板 Template Spec；跑通 1 个模板端到端 | Spec v1 文档 + 1 条真实成片 |
| **M1 建底座** | 引擎层：解释器 / 两段式生成 / 质检 / 合成 | 内部可用的生成 API |
| **M1'（并行）** | 内容团队产出首批 40 个模板 | 40 份验证通过的 Spec |
| **M2 通流程** | 页面 ②③④⑤⑥⑦⑧ 全通 | 可对外测试的完整产品 |
| **M3 扩规模** | 补品类（运动鞋服/腕表）、商品档案 P1 | — |
| **M4 参考视频** | P2：上传参考视频反解成 Spec | — |

**M0 是唯一的强前置。** Spec 没定就让内容团队开工，产出的东西大概率要返工重写。建议 M0 用 1-2 周，只做一个模板，但把从拆解到出片的每个环节都真跑一遍——所有格式问题会在这一遍里全部暴露。

### 4.3 待决事项

| # | 问题 | 影响 |
|---|---|---|
| 1 | "SD 2.0" 确认是 Seedance 2.0？单镜头时长上限、多图参考能力如何？ | 决定分镜结构和整条管线 |
| 2 | 单条成片的成本预算上限？ | 决定能重跑几次、能不能多候选择优 |
| 3 | 用户素材的最低假设——只有白底图，还是引导补拍多角度？ | 决定 `fallback` 策略和运镜自由度 |
| 4 | 首批是否要旁白配音（TTS）？ | 决定要不要接音色库、做文案时长对齐 |
| 5 | 内容团队人力规模？ | 直接决定首批模板数和 M1' 排期 |
| 6 | 成片是否带 AI 生成标识/水印？免费版策略？ | 合规 + 商业化 |

### 4.4 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| **A 类镜头还原度不达标** | 片子不可用，用户直接流失 | 质检闸门 + 自动重跑 + 合成兜底（§2.3） |
| **模板生产速度跟不上** | 上线时库太薄，用户找不到自己品类 | 首批收窄到 4 品类；耳机做深而非全品类做浅 |
| **两段式生成中途流失** | 用户在故事板确认页跑了 | 故事板出图控制在 40s 内；支持离开后回来继续 |
| **Demo 素材版权** | 现有 demo 素材全部是真实品牌广告 | 已有规范（模板名品牌中立、仅内部评估）；**上线前必须全部换成自产样片** |
| **链接解析质量参差** | 用户以为贴链接就完事，拿到废片 | 商品确认页强制人工确认；UI 明确要求上传干净原图 |

## 附：与首页设计方案 v1 的差异

| 项 | v1 首页方案 | 本方案建议 |
|---|---|---|
| 品类数 | 8 → 实做 6 | 首批 **4** |
| 题材数 | 10 | 首批 **6**（去掉人物出镜类 + 开箱） |
| 题材命名 | 行业词（美学 B-Roll、痛点对比） | 目的导向词（生活场景氛围、对比出效果） |
| 主路径 | 首页 → 模板库筛选 | 首页 → **商品确认 → 自动推荐** → 模板库降为二级 |
| 生成流程 | 未定义 | **两段式**：先故事板确认，再出成片 |

首页 Demo 本身不需要推翻——电视机隐喻和频道键是好的视觉资产，主要改动是**频道键上的文案**和**输入框提交后的去向**（原方案是跳模板库占位页，建议改为跳商品确认页）。
